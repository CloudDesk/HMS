## Findings and stop gates before implementation

- Readiness GET and completion-history GET require Consultation View. History is explicitly null until finalization exists; version zero is usable only after that successful null response, never after an error. History supplies authoritative finalization versions, deferrals, override snapshots, approval actor/time and amendment episodes. Discard unneeded raw summary/configuration snapshots and replay fingerprints at the frontend API boundary.
- Deferral uses Override permission, original finalization version, an actual same-encounter task/order, reason, future due date or review plan and active same-branch/department doctor. Override uses the same exact permission, reason and complete original set of unmet server requirement codes. Backend rechecks configuration, eligibility, scope, versions and transactions. Neither action is completion or review.
- **Final completion is gated:** current mandatory-task check uses `mandatoryTasks.every(...)` without requiring tasks for configured codes. Zero mandatory tasks can pass. The readiness contract also lacks VA/omission, independent-eye/examination/IOP acknowledgement and other detailed FSD prerequisite evidence. Do not invent frontend clinical pass rules or enable final approval on incomplete backend evidence. The API owner must resolve these before completion/reapproval UI is enabled.
- **Amendment writes/reopen are gated:** appendAmendment only adds free-form section/before/after journal data. It does not validate section schemas or apply changes to source clinical records or the new summary snapshot. Normal clinical writes remain locked while AMENDMENT_OPEN. Completion rebuilds the unmodified source projection. Do not expose an editor or start an episode that has no supported correction path; do not represent journaling as a corrected clinical record. Existing episodes/history remain read-only.
- **Full summary is gated:** summary reuses the raw broad doctor-review projection, including unfiltered historical results, noted in B4. No approved permission/eye/protocol-safe consolidated summary serialization exists. Do not reconstruct or render unrestricted histories. Show contracted completion/readiness/history metadata and existing section links without pretending it is the full FSD consultation summary.
- **Generic OPD bypass is a backend gap:** the generic consultation complete service does not check specialty context/readiness. No authoritative specialty flag exists in the shared visit DTO. Frontend cannot secure this across direct URLs/clients by guessing specialty from doctor display text. Preserve General OPD/Dental and report the required backend guard. Specialty-origin shared links may carry a UI marker to prevent accidental completion in that flow; the marker is never an authorization boundary.
- No new grants, mock data, browser clinical persistence, lifecycle enums, signature certification, publication or B6 work. Live clinical acceptance still requires an authenticated session and approved fixtures.
